# Coach 2: Training Plan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A structured training plan in pace: sessions and blocks in a local file, pushed to Garmin one session at a time (or in batches), and compared against what was actually done.

**Architecture:** `pace/plan.py` is the plan model on top of `pace/store.py` (coach plan 1).
`pace/sports.py` maps Garmin activity type keys to sport families.
`pace/workoutwrites.py` holds the three Garmin workout write specs shared by `workout push/schedule/delete` and the plan.
`pace/planpush.py` runs push/unpush; `pace/matching.py` is a pure matcher of sessions to activities.
`pace/commands/plan.py` wraps everything in the envelope; `workout calendar` is a new read in `pace/commands/workout.py`.

**Tech Stack:** Python 3.14, typer, garminconnect (via `pace.api.safe_call`), pytest + typer `CliRunner` with `safe_call` monkeypatched (pattern: `tests/test_workout_cmd.py` `fake_api`).

**Spec:** `docs/superpowers/specs/2026-11-17-coach-plan-design.md` section 2 (Plan), Constraints, Anti-goals (drift).
Plan 2 of 4; depends on plan 1 (`pace.store`, `pace.diary`).

## Global Constraints

- Every write contract of the 2026-09-04 spec section 7 holds: one envelope, `--dry-run` on every Garmin write showing the exact payloads, writes never read the cache, success invalidates affected cache keys; Garmin writes go through `pace.writes.run_write`.
- Plan file `$PACE_HOME/plan.json`; archive dir `$PACE_HOME/plans/`; read-modify-write via `plan.transaction()` (plan 1 `store.locked`); never nest two locks on the same path (flock self-deadlocks); corrupt file -> `internal` with path hint, never overwritten.
- **Garmin invariant:** a session has a Garmin workout if and only if `garmin is not None`; `status == "pushed"` if and only if `garmin.schedule_id` is set.
  Every drift guard (remove, new plan, status change) keys on `garmin is not None`, not on `status`.
- Session `sport`: `running | cycling | swimming | walking | hiking | strength | mobility | other`; only the first five can carry a `workout` and be pushed.
- Session `intensity`: `rest | easy | moderate | hard`.
- Stored `status`: `planned | pushed | skipped | done` (`done` stored only by hand, for sessions Garmin does not record, user's call 2026-11-17).
  Derived only (from `plan status`): `done`, `modified`, `missed`, `unconfirmed`, `rest`.
- Pushed workout names are prefixed exactly `"pace: "`.
- `MODIFIED_TOLERANCE = 0.20`, defined once in `pace/plan.py`: actual duration or distance differs from the target by more than 20 %.
- Deleting a workout on Garmin removes its schedules; deleting an already deleted workout returns 404 `not_found` (both verified live 2026-11-17); 404 on delete counts as success.
- Past sessions (date < today) are never pushed, re-pushed or unpushed: deleting their workout would erase that day from the Garmin calendar (user's call 2026-11-17).
- Re-pushing a pushed, non-stale session is skipped unless `--force` (user's call 2026-11-17).
- The Garmin month view returns days of the neighbouring months (the November view starts on 25 October, verified 2026-11-17): calendar items are filtered by date and deduplicated by schedule id.
- Weeks and days are local dates; pure functions take `today: date` for tests; commands use `date.today()`.
- No real Garmin ids in tests or docs (synthetic ids only).
- ASCII only; markdown one sentence per line; pytest and ruff clean at every commit; no Claude attribution.

## Review Focus

1. A batch push where the second session fails (rate limit, Garmin rejection): the first stays pushed and recorded, the second reports its error, and re-running the same command skips the first (not stale) instead of duplicating it. Test in Task 3.
2. Two pace processes pushing the same session (terminal + Telegram run): the second waits for the push lock and then sees the session pushed and skips it; no duplicate workout. Test in Task 3.
3. A session edited (`plan set --date`) while its push is in flight: the push persists ids and marks the session `stale`, so the next push moves it. Test in Task 3.
4. A workout uploaded but not scheduled (schedule call failed), then `plan remove` or `plan set --status skipped`: refused while `garmin` is set; the next push deletes that workout first. Test in Tasks 1 and 3.
5. Two runs on one day against one or two sessions: one-to-one, global closest-duration pairing; a run started from the pushed workout matches by `workoutId` regardless of duration. Test in Task 4.

def upload_spec(dsl: dict) -> WriteSpec                       # upload_workout; invalidate ("get_workouts:",)

- Produces (`pace.planpush`):

```python
async def push_sessions(ids: list[int], *, dry_run: bool, force: bool, today: date) -> dict
async def unpush_sessions(ids: list[int], *, dry_run: bool, today: date) -> dict
```

  Return `{"results": [{"id", "ok", "action": "pushed" | "skipped" | "unpushed" | "noop", "steps": [{"step", "payload", "id"}], "error": {...} | None, "garmin": {...} | None, "session": {...} | None}], "done": n, "failed": n}`.
  Envelope is `ok: false` (first error) only when every session failed and no Garmin write landed; otherwise `ok: true` with per-session results.
  The whole call holds a push lock, `store.locked(plan_path().with_name("plan-push.json"))` (a different path from `plan.json`, so the short per-step `plan.transaction()` does not nest on the same lock); a second push/unpush waits up to the lock timeout.
  Per session, after re-reading it:
  - Refuse (per-session `bad_args`, no call): unknown id; `skipped` or `done` status; sport not PUSHABLE; `workout` None; date < today.
  - Skip (`action: "skipped"`, no call): `status == "pushed"`, not stale, `force` False.
  - Steps, each a `run_write`, each persisted right after it lands inside a short `plan.transaction()` that reloads the file:
    1. If `garmin` is set: `delete_spec(garmin.workout_id)` (404 = done) -> persist `garmin = None`, `status = "planned"`, `pushed_as = None`.
    2. `upload_spec(dsl)` with `name = WORKOUT_PREFIX + dsl["name"].strip()` unless it already starts with the prefix; a response without `workoutId` is an error -> persist `garmin = {"workout_id": id, "schedule_id": None}`, `pushed_as = {"date", "workout"}` as read before the upload.
    3. `schedule_spec(workout_id, date)` -> persist `schedule_id`, `status = "pushed"`.
  - Persist re-derives `stale` from `pushed_as` against the current file, so an edit made during the network calls shows as stale.
  - If the session vanished from the file before a persist, or the persist itself fails (lock busy), the result is an error that carries the landed Garmin ids (`garmin` key) so the caller can clean up with `workout delete`.
  `unpush`: refuse date < today; a session without `garmin` -> `noop`; else `delete_spec` (404 ok) -> persist `garmin = None`, `status = "planned"`, `pushed_as = None`, `stale = False`.
  `--dry-run`: no lock, no network, no file change; each result lists the exact payloads of the steps it would run.

### Task 4: Matching, `plan status`, `workout calendar`

**Files:**
- Create: `pace/matching.py`
- Modify: `pace/commands/plan.py`, `pace/commands/workout.py`, `pace/commands/schema.py`, `pace/api.py` (comment), `docs/CONTRACT.md`, `README.md`, the spec (post-hoc notes)

**Interfaces:**
- Consumes: Task 1 (`sessions_in`, `family`, `UNTRACKED`, `MODIFIED_TOLERANCE`); `cached_call("get_activities_by_date", from, to, None, ttl=600)` as in `activity list`; `cached_call("get_activity", id, ttl=86400)` + `pace.effort.with_effort` for RPE/feel (same cache key as `activity show`, so a check-in reuses it).
- Produces (`pace.matching`):

```python
def match(sessions: list[dict], activities: list[dict], *, today: date,
          effort: dict[int, dict] | None = None) -> dict    # effort: activityId -> {"rpe", "feel"}
```

  Activities are Garmin list rows (`activityId`, `activityType` dict or key, `startTimeLocal`, `duration`, `movingDuration`, `distance`, `elevationGain`, `averageSpeed`, `averageHR`, `workoutId`).
  Activity duration = `movingDuration` if > 0 else `duration`.
  Algorithm, each activity used at most once:
  1. Manual link: a session with `activity_id` takes that activity; if the activity is not in the fetched rows, it is still matched with `actual = {"activity_id": id}` and other fields None (the manual link always wins, it never falls back).
  2. Workout link: a remaining session with `garmin` whose `workout_id` equals an activity's `workoutId` (any date in range) takes it.
  3. Closest pairing: all (session, activity) pairs with the same local date (`startTimeLocal[:10]`) and `family(type) == sport`, sorted by key `(diff, session id, startTimeLocal, activityId)` where diff = `abs(duration - target.duration_s)` if the session has a duration target, else `abs(distance - target.distance_m)` if it has a distance target, else `0`; take pairs in order, skipping any whose session or activity is already used.
  Classification:
  - matched -> `modified` if a non-null duration or distance target differs from the actual by more than `MODIFIED_TOLERANCE` (missing actual values do not count), else `done`.
  - unmatched -> stored `done` -> `done` (`actual None`); stored `skipped` -> `skipped`; intensity `rest` -> `rest`; date < today -> `unconfirmed` for UNTRACKED sports, `missed` otherwise; else stored status (`planned` / `pushed`).
  Output: `{"days": [{"date", "sessions": [{"id", "title", "sport", "intensity", "status", "target", "stale", "actual": {"activity_id", "type", "duration_s", "distance_m", "elevation_m", "avg_pace_s_per_km", "avg_hr", "rpe", "feel"} | None}], "unplanned": [{"activity_id", "type", "sport", "duration_s", "distance_m", "avg_hr", "rpe", "feel"}]}], "totals": {sport: {"planned": {"duration_s", "distance_m"}, "actual": {"duration_s", "distance_m"}}}, "intensity_planned_s": {intensity: seconds}, "intensity_missing": n}`.
  `avg_pace_s_per_km` = `1000 / averageSpeed` when speed > 0, else None.
  Totals: planned = all sessions in range except `skipped` and `rest`; actual = all activities in range (matched and unplanned) by family; `intensity_missing` counts sessions without a duration target.
  Days without sessions or activities are omitted.
